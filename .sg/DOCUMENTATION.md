## 8. Notable Decisions & Caveats

### Omitted attributes (from discovery null values)

The following attributes were discovered with `null` values and are intentionally omitted from the resource definition to avoid spurious drift:

- **`labels`** — GCP BigQuery labels require special handling; user-supplied labels are stored in state but empty label maps cause drift. Since discovery reported `null`, labels are not included.
- **`clustering_fields`** — Null in discovery; omitted (table is not clustered).
- **`expiration_time`** — Null in discovery; omitted (table does not expire).
- **`kms_key_name`** — Null in discovery; omitted (no customer-managed key).
- **`range_partitioning`** — Null in discovery; omitted (table is not range-partitioned).
- **`time_partitioning`** — Null in discovery; omitted (table is not time-partitioned).

### Explicit defaults

- **`require_partition_filter = false`** — explicitly set in code to match discovery value and GCP provider default. Improves clarity.
- **`description = ""`** — empty string in tfvars; matches discovery value.

### Dataset management

The dataset `sg_infra_2_code` is a **reference**, not a managed resource. It was not discovered as an independent resource and is assumed to exist. To manage it, add a `google_bigquery_dataset` resource or import it separately.

### Lifecycle / ignore_changes

No `lifecycle` blocks are applied. All resource attributes are managed.

### Import stability

The import key format (`project/dataset/table`) is stable and matches the GCP BigQuery API standard. If a table is renamed or moved to another dataset, the resource must be re-created or re-imported under a new address.
